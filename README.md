# Prime Sport — презентация как отдельный сайт

Готовый статический сайт: HTML, CSS, JavaScript и локальные изображения.
Откройте `index.html` в Chrome или Edge. На хостинг загружайте содержимое
этой папки: `index.html` должен находиться в корне публикуемого сайта.
Установка зависимостей, команда сборки, сервер приложений и API-ключи не нужны.
Все ресурсы для показа включены; внешние ссылки на источники открываются по нажатию.

## Публикация

1. Распакуйте ZIP. Загрузите распакованные файлы в отдельный репозиторий GitHub,
   сохранив вложенность `assets/native/` и остальные имена файлов.
2. Подключите репозиторий к вашему статическому хостингу. Каталог публикации —
   корень репозитория, стартовый файл — `index.html`, команда сборки — отсутствует.
3. В панели хостинга добавьте ваш субдомен. Создайте именно те DNS-записи,
   которые укажет выбранный хостинг, и подключите HTTPS.

Если используете GitHub Pages: откройте Settings → Pages, выберите публикацию
из ветки `main`, папку `/ (root)`. В архиве есть `.nojekyll`.
Входной `index.html` уже находится в корне.
[Инструкция GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

Для субдомена в GitHub Pages сначала укажите его в Settings → Pages → Custom domain,
затем создайте DNS CNAME на `<user>.github.io` или `<organization>.github.io`
без имени репозитория. После настройки включите HTTPS.
Конкретные домен и аккаунт здесь не заданы.
[Настройка субдомена](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site#configuring-a-subdomain).

## Проверка после загрузки

- Открывается главная, изображения и шрифты загружаются.
- Колёсико мыши, кнопки навигации и стрелки переключают слайды.
- Предпоследний слайд — «Спасибо за внимание!», последний — вопросы для обсуждения.
- Клавиша End и ссылка `#discussion` приводят к вопросам (19 / 19).
- Схема процесса, масштабирование и раскрытие фотографий работают.
- На телефоне длинные слайды прокручиваются, меню доступно.

Внутренняя навигация использует фрагменты URL (`#fit`, `#discussion`):
перенаправление всех серверных путей на `index.html` не требуется.
Пути к ресурсам относительные, поэтому сайт можно размещать и на субдомене,
и в подпапке. В архиве 19 слайдов; анимация появления сохранена.

## Управление

Колёсико вниз/вверх — следующий/предыдущий слайд. На длинном слайде сначала
прокручивается его содержимое; у края нужно начать новое движение колёсика.
Стрелки, PageDown/PageUp, пробел/Shift+пробел — вперёд/назад.
Home/End — первый/последний слайд. F — полный экран. Esc — закрыть просмотр.
P — пауза движения. R — повтор анимации. Ctrl+колёсико в схеме — масштаб.

## Анимация при прокрутке

Блоки плавно появляются при первом попадании в видимую область и остаются
видимыми при возврате к разделу. Прокрутка пальцем не ждёт остановки жеста.
На сенсорных устройствах постоянное декоративное покачивание отключено;
при `prefers-reduced-motion` содержимое показывается сразу. Кнопка повтора
и клавиша R по-прежнему повторяют появление текущего раздела.

Регрессионная проверка: установите Playwright в окружении для тестирования
и запустите `node qa/motion-smoke.cjs` (нужен Chrome; для другого Chromium
можно задать `CHROME_PATH`). Тест проверяет телефонный и настольный размеры,
непрерывную прокрутку и возврат к прочитанному, повтор анимации, фотографии,
сенсорный жест, клавиатуру, колёсико и уменьшенное движение.

`HANDOFF.md` содержит задание для другой нейросети.
`release-manifest.json` содержит список файлов и SHA-256 для проверки переноса.
